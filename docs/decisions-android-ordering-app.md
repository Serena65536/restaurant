# 决策记录：饭店点餐 App 的形态与栈

日期：2026-02-15（会话内）
状态：**方向已定，等待开工确认**

## 需求约束（来自店主）

- 店主要能在手机上维护分区与菜品（名称、图片、价格），分区可自定义并归类菜品
- 顾客界面：左分区 / 右菜品，纵向滚动，参考美团外卖下单页
- 顾客需绑定手机号才能下单；下单生成订单号；可选「继续加菜」或「立刻结账」
- 退出应用后，未结算订单按手机号保留
- 结账可选微信支付或支付宝；成功后显示结账成功，金额进入店主账户
- 先不上架应用商店，本地能用就行
- 仅用于测试跑通点餐流程，不用于实际经营；对外用 Cloudflare Tunnel 免费临时域名暴露本机后端

## 候选方案

| 方案 | 形态与栈 | 优点 | 缺点 |
|---|---|---|---|
| A | React Native 0.79 裸 CLI → 签名 APK（关新架构免 NDK）+ Node/Express + `node:sqlite` | 真原生 UI、真安装包、完全本地、无审核 | 需一次性装 JDK + Android SDK（约 2–3 GB 下载） |
| B | Expo + Expo Go 扫码运行 | 免 SDK、真原生界面、迭代最快 | 需要手机上装 Expo Go，且依赖局域网连开发机 |
| C | H5 网页 / PWA 加到主屏 | 零安装、微信与支付宝支付可共存 | 渲染是网页，不是原生控件；不符合「原生 App」诉求 |

## 决定

选 **A**：React Native 裸 CLI 出 APK，后端本机 Node + SQLite，支付先模拟（通道可插拔）。

决定理由（关键一条）：用户明确要「原生 App、打 APK 装到安卓」且不上架商店，A 是唯一同时满足「原生控件 + 自包含 APK + 完全本地」的路线；B、C 作为 M0 工具链失败时的备选保留。

配套决定：
- 登录用手机号 + 密码（免短信资质与费用）
- **对外访问用 Cloudflare Tunnel 的免费临时域名**（`cloudflared tunnel --url http://localhost:8080`），后端只监听 127.0.0.1：手机连 4G 也能用、自带 HTTPS（绕过 Android 9+ 明文限制）、免备案、免开防火墙；代价是 URL 每次重启变化，所以 App 必须支持运行时改服务器地址。已实测：4 秒生成域名，公网访问返回 502（隧道通、后端未起）。
- 支付先 mock，`payments.channel` 预留 wechat / alipay，真通道只换配置与密钥
- 关新架构（`newArchEnabled=false`）省掉 NDK/CMake 约 3 GB
- 图片存本机 `data/uploads`，正式版换对象存储
- `node:sqlite` 仅用于演示，数据访问层隔离，将来换 MySQL/Postgres

## 仍可能改变决定的待定项

- M0 工具链若装不上：切 B 或 C（界面上大部分代码可复用）
- 隧道若不稳定（免费域名有限速/断线）：改 Cloudflare 命名隧道 + 自有域名，或退回局域网直连
- 真收款需要营业执照 + 微信商户号 / 支付宝签约，届时 M4 的 mock 通道替换为真实通道
