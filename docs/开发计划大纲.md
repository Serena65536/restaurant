# 饭店点餐 App（安卓本地版）· 开发计划

> 版本：v3（已按你的选择定稿方向，**尚未开工**）

## 0. 一句话目标

一个能装进安卓手机的**原生 App**：店主在手机上维护「分区 + 菜品（名称 / 图片 / 价格）」，顾客用手机号密码登录后，像美团外卖下单页一样左分区右菜品点餐，下单得到订单号，可「继续加菜」或「立刻结账」；结账走微信 / 支付宝（先模拟，资质到位换真通道），成功后显示结账成功、金额计入店主账户；顾客中途退出，未结算订单按手机号在服务端保留，重新登录自动回到原订单。

## 3. 技术选型（为什么这样选）

- **前端：React Native 0.79（裸 CLI，不用 Expo）**
  出的是真 APK、真原生控件；关掉「新架构」（`newArchEnabled=false`）就不需要 NDK / CMake，能省约 3 GB 下载和大量编译时间。依赖克制到最少：核心库 + `react-native-image-picker`（店主选图）两个；路由、状态、列表、购物车全部自己写，减少打包踩坑。
- **后端：Node.js + Express + `node:sqlite`（SQLite 单文件数据库）**
  不装 MySQL，不编译原生模块，`data/app.db` 一个文件就是全部数据，方便备份和搬走。数据访问层单独一层，将来换 MySQL 只改这一层。
- **图片：存本机 `data/uploads`，后端静态托管**（正式上线再换 OSS / COS）。
- **对外访问：Cloudflare Tunnel**
  后端只监听 `127.0.0.1:8080`（不暴露局域网），由 `cloudflared tunnel --url http://localhost:8080` 转发到公网临时域名。好处：手机连 4G 也能用、自带 HTTPS（Android 9+ 的明文 HTTP 限制自动绕过、不用改防火墙）、不需要备案。代价：URL 每次重启都变 ⇒ App 必须能在运行时配置服务器地址（见 §5）。
- **通信：手机 → `https://<随机名>.trycloudflare.com`**
  为此额外加一个「服务器地址」设置项：首次启动填写、本机持久化保存，扫码或粘贴均可；同时保留直连 `http://<局域网IP>:8080` 的输入能力作为兜底（这种情况下才需要 `network_security_config` 放行明文）。
- 打包：`gradlew assembleRelease`，用 JDK 自带 `keytool` 生成签名，出一个自包含的 APK（不依赖 Metro，装到手机上直接开）。

## 4. 数据模型

```
users       用户(id, 手机号唯一, 密码哈希, 角色 owner/customer, 昵称, 创建时间)
categories  分区(id, 名称, 排序, 是否显示)
dishes      菜品(id, 分区id, 名称, 图片, 价格(分), 描述, 是否上架, 是否售罄, 排序)
orders      订单(id, 订单号唯一, 顾客id, 手机号, 状态 OPEN/PAID/CANCELLED, 金额(分), 创建时间, 支付时间)
order_items 明细(id, 订单id, 菜品id, 名称快照, 单价快照, 图片快照, 数量)
payments    支付单(id, 订单id, 通道, 金额, 商户单号唯一, 状态, 支付时间, 原始回调)
```

- 金额一律用「分」存整数，服务端重算，不信前端传金额。
- 明细存下单时的名称 / 单价 / 图片快照，店主改价不影响历史订单。
- 未结算订单 = `OPEN`，跟手机号绑定；**加菜 = 往同一张 OPEN 订单追加明细，订单号不变**。

## 5. 页面与交互

顾客端
0. 首次启动：填「服务器地址」（粘贴或扫码拿到 trycloudflare 域名），存本机，之后自动带上；地址不对时给一句人话提示「连不上服务器，请确认电脑上的隧道是否开着」。
1. 登录 / 绑定手机号（手机号 + 密码，首次自动注册）
2. **点餐页（核心）**：顶部店名；左侧分区竖排（选中高亮、随右侧滚动自动高亮）；右侧菜品卡片（图 / 名 / 价 / 加号，售罄置灰）；底部购物车条（数量气泡、合计、去结算）；左栏点击 → 右侧滚动定位，右侧滚动 → 左栏联动高亮。
3. 购物车：增减、清空、去下单。
4. 订单页：订单号、明细、合计、**[继续加菜]** **[立刻结账]**。
5. 支付页：微信 / 支付宝二选一 → 「支付中」→ **结账成功 + 金额**。

店主端（同一个 App，登录后按角色进不同首页）
1. 管理首页：今日营业额、订单数、待处理订单。
2. 分区管理：新增、改名、排序、隐藏。
3. 菜品列表 + 编辑：名称、价格、图片（调系统相册）、所属分区、上下架 / 售罄、排序。
4. 订单列表 + 详情：今日 / 全部订单、金额、支付状态。

## 6. 核心流程

**下单**：选菜 → 服务端校验上架 / 价格 → 建 OPEN 订单（生成订单号）→ 订单页。
**加菜**：订单页「继续加菜」→ 回点餐页 → 明细追加到同一 OPEN 订单 → 金额累加。
**结账**：选通道 → 建支付单（商户单号 = 订单号 + 时间戳）→ 调起支付 → 回调验签 + 幂等 → 订单变 PAID → 前端轮询确认 → 结账成功。
**退出再进**：登录后按手机号查 OPEN 订单 → 直接恢复到订单页。
**订单号**：4 位随机数（1000–9999），生成时避开库里已有的号；4 位用光才退到更长号。商户单号另生成，互不复用。
**超时**：OPEN 订单默认 24 小时自动关闭（可配置）。

## 10. 风险与备选

1. **工具链装不上 / 太慢** → 备选一：Expo Go 扫码运行（免 SDK，真原生界面）；备选二：网页版装到手机主屏（PWA）。两者都能复用大部分界面代码，我会在 M0 卡住时直接切换并告诉你。
2. **临时域名每次重启都变** → App 内可随时改服务器地址，`start.ps1` 每次启动把新域名和二维码打在屏幕上，改一次 5 秒。
3. **免费 quick tunnel 无 SLA，可能被限速或断开** → 只做流程验证用；断了会换域名，需要重新填地址。真要长期用，换 Cloudflare 命名隧道 + 自己的域名（免费账号即可，但要一个域名）。
4. **手机连不上电脑** → 先查隧道进程是否还活着；兜底方案是同一 WiFi 直连 `http://局域网IP:8080`（这种情况要放行防火墙 8080 并允许明文 HTTP）。
5. **Android 9+ 禁明文 HTTP** → 走隧道时是 HTTPS 不受影响；直连兜底时才需要 `network_security_config` 放行。
6. **`node:sqlite` 是实验性 API** → 只用于本地演示，正式上线换 MySQL / Postgres，数据访问层已隔离。
7. **模拟支付不是真钱** → 上线前必须接商户号（微信 / 支付宝都要营业执照）。
8. **图片存本机磁盘** → 只适合演示，正式版换对象存储。
